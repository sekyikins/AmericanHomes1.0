# AmericanHomes — Defect Register

**Audit & QA Window:** 20 November 2026 – 21 November 2026

| Defect ID | Severity | Source Phase | Description | Resolution | Status |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **DEF-001** *(ISS-001)* | **Critical** | Compliance Audit | IDOR on `PATCH /notifications/:id/read` and `GET /notifications/receipt/:orderId` allowed any authenticated user to mark another user's notification read or view another customer's receipt. | Scoped `markRead` to `user.id` and restricted `getDigitalReceipt` to `STAFF` or the owning customer (`ForbiddenException` otherwise). | **Resolved** |
| **DEF-002** *(ISS-002)* | **Critical** | Compliance Audit | `OtpService.verifyOtp` returned `true` unconditionally without checking OTP code, expiry, or attempts. | Implemented SHA-256 hashed OTP store, 5-min TTL, max 5 attempts, single-use invalidation, and `'123456'` dummy fallback when live OTP API keys are not configured. | **Resolved** |
| **DEF-003** *(ISS-007)* | **High** | Compliance Audit | `POST /auth/revoke-other-sessions` was a no-op; password changes and staff deactivation did not invalidate existing JWTs. | Added `User.sessionVersion`, `ver` claim in JWTs, `AuthGuard` version check, and version increment on session revocation, password change, and staff deactivation. | **Resolved** |
| **DEF-004** *(ISS-003)* | **High** | Compliance Audit | `/checkout` hardcoded `disclosedDefectsAcknowledged: true` without surfacing `defectDisclosures` or requiring customer consent. | Propagated `defectDisclosures` through `CatalogProduct` -> `CartItem` -> `/checkout` with mandatory consent checkbox before payment. | **Resolved** |
| **DEF-005** *(ISS-004)* | **High** | Compliance Audit | `GET /payments/verify/:reference` queried Paystack without settling the payment, consuming `StockHold`s, or syncing `SalesOrder.paymentStatus`. | Extracted `settleVerifiedPayment` and invoked it from both `handleWebhook` and `verifyPayment`. | **Resolved** |
| **DEF-006** *(ISS-005)* | **Medium** | Compliance Audit | `NotificationsService.queueWhatsApp` used `eventType: 'WHATSAPP_MESSAGE'`, which did not match `OutboxProcessor` (`startsWith('whatsapp.')`), and delivery attempts were not logged. | Aligned `eventType` to `'whatsapp.template'` and added `NotificationDeliveryAttempt` (`SENT`/`FAILED`) logging in `OutboxProcessor`. | **Resolved** |
| **DEF-007** *(ISS-006)* | **Medium** | Compliance Audit | `ReportsService.generateExport` ignored `from`/`to` filters, only returned CSV even when `XLSX`/`PDF` was requested, and did not check entity permissions (`FR-RPT-005`). | Added date filtering, per-report entity permission checks, and zero-dependency `.xlsx` and `.pdf` binary/base64 generators wired into `FinanceWorkspace.tsx`. | **Resolved** |
| **DEF-008** | **High** | Phase 2 E2E QA | `OtpService.isProviderConfigured()` treated placeholder `OTP_PROVIDER_URL` / `OTP_API_KEY` values in `.env` as live credentials, breaking dummy `'123456'` verification during local/staging testing. | Updated `OtpService` to require both `otpProviderUrl` and a non-placeholder `otpApiKey` before exiting dummy mode. | **Resolved** |
| **DEF-009** | **Medium** | Phase 5 Production Review | `apps/api/src/main.ts` lacks `helmet` security headers and HTTP rate limiting (`@nestjs/throttler`) on auth/OTP endpoints, and exposes `/api/docs` unconditionally in production. | Implemented `SecurityHeadersMiddleware`, `AuthRateLimitMiddleware` on `/api/auth/*`, `x-powered-by` disablement, production `JWT_SECRET`/`CORS_ORIGINS` startup guards, `/api/docs` production gate in `main.ts`, and security headers in `apps/web/next.config.mjs`. | **Resolved** |
| **DEF-010** | **Low** | Phase 1 Verification | `@americanhomes/contracts` package exists and typechecks, while `apps/api` and `apps/web` still maintain parallel local DTO/API types. | Deferred maintainability cleanup; current contracts are verified aligned via E2E tests. | **Deferred** |
| **DEF-011** | **Medium** | Phase 2 E2E QA | `NotificationsService.updatePreferences` passed raw request `dto` directly into Prisma `upsert`, causing `500 Internal Server Error` (`PrismaClientValidationError`) if any extra property was sent. | Added explicit boolean field allowlist (`productRequests`, `reservations`, `ordersPayments`, `availability`, `promotions`) in `NotificationsService.updatePreferences`. | **Resolved** |
